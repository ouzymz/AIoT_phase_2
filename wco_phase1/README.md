# WCO Phase 1 — Data Collection Server

FastAPI gateway that sits between the ESP32-S3 capture rig and Google Drive. The ESP32 calls `/uploadTrainingImage` (see the project root README); that handler then POSTs a labelled JPEG to this server's `/uploadGoogleDrive`. The server validates the labels and writes the file to a canonical Drive folder.

The deliberately thin design (single endpoint, no auto-labelling, no validation loop) is documented in Section 3.3 of the project report. The operator labels each sample physically before capture, so the server only needs range validation on the three label flags before forwarding to Drive.

---

## Install

```bash
cd wco_phase1
pip install -r requirements.txt
```

`requirements.txt`:

- `fastapi`, `uvicorn[standard]`, `python-multipart` — HTTP + multipart parsing
- `google-api-python-client`, `google-auth`, `google-auth-oauthlib` — Drive v3 client
- `python-dotenv`, `opencv-python-headless`

---

## OAuth setup

The Drive client expects two credential files in this directory:

- `client_secret_*.json` — OAuth 2.0 client downloaded from Google Cloud Console
- `token.pickle` — generated by running `python generate_token.py` once on a machine with a browser

**Do not commit these files.** The `.gitignore` patterns `wco_phase1/*.json` and `wco_phase1/*.pickle` cover them, but always check `git status` before pushing. The repository was push-blocked once after these credentials slipped through; if they leak again, revoke the service account key and OAuth client immediately in Google Cloud Console before doing anything else.

A `.env` file alongside `main.py` may carry Drive folder IDs or override paths. It is gitignored.

---

## Run

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

On startup the server prints its local IP. Put that value into `SERVER_IP` in the ESP32's `include/config.h`.

## Endpoints

### `POST /uploadGoogleDrive`

Receives the JPEG-plus-labels payload from the ESP32 and writes it to Drive.

**Body:** `multipart/form-data`

- `file` — JPEG bytes
- `turbidity` — `0` or `1`
- `particle` — `0` or `1`
- `color` — `0` or `1`

**Response:**

```json
{ "status": "ok", "filename": "t1-p0-c1.jpeg" }
```

The filename encodes the three labels. Drive's internal file ID disambiguates samples that share the same `(t, p, c)` combination, so no client-side unique key is needed.

### `GET /health`

```json
{ "status": "ok", "uptime_seconds": 124.3 }
```
